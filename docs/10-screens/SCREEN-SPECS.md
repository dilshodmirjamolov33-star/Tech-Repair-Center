# Спецификация экранов — Tech Repair Center

## 01. Главная и проверка статуса
**Файл приложения:** `index.php` · **Доступ:** публичный.

Пользователь вводит номер квитанции. При совпадении система показывает модель устройства, номер квитанции, дату приёма, текущий статус и шкалу из пяти статусов. Стоимость и срок гарантии появляются при готовом/выданном заказе в соответствии с кодом страницы.

## 02. Вход сотрудников
**Файл приложения:** `login.php` · **Доступ:** сотрудники.

Поля: логин и пароль. При успешной проверке хеша пароля создаётся сессия и пользователь перенаправляется на `panel.php`. Ошибка отображается без раскрытия существования конкретного логина.

## 03. Панель заказов
**Файл приложения:** `panel.php` · **Доступ:** admin, receptionist, master.

Таблица содержит квитанцию, клиента, телефон, устройство, назначенного мастера, статус, сумму и действие открытия. Есть фильтрация по статусу и поиск по квитанции, имени и телефону. Для мастера серверный запрос ограничен назначенными ему заказами.

## 04. Приём нового устройства
**Файл приложения:** `order_new.php` · **Доступ:** admin, receptionist.

Поля: имя клиента, телефон, тип устройства (телефон/ноутбук), бренд, модель, IMEI/серийный номер, тип неисправности, мастер (необязательно), гарантия в днях и описание неисправности. После сохранения генерируется номер квитанции, записывается начальный статус и открывается квитанция.

## 05. Детали заказа
**Файл приложения:** `order.php?id=...` · **Доступ:** admin, receptionist, назначенный master.

Содержит данные устройства и клиента, описание неисправности, назначение мастера (для сотрудников с расширенными правами), изменение статуса, журнал статусов, список установленных деталей, стоимость работы, стоимость деталей и общую сумму. Добавление деталей проверяет остаток на складе и выполняется транзакционно.

## 06. Склад запчастей
**Файл приложения:** `parts.php` · **Доступ:** admin, receptionist.

Таблица: наименование, SKU, цена, остаток, минимальный остаток и форма прихода. Отдельная форма создаёт новую позицию. Низкий остаток визуально выделяется.

## 07. Квитанция
**Файл приложения:** `receipt.php?id=...` · **Доступ:** admin, receptionist.

Документ формата A5 содержит номер и дату, данные клиента, модель устройства, серийный номер, описание неисправности, назначенного мастера, условие гарантии и данные приёмщика. Действия: печать и экспорт в PDF.

## 08. Обзор администратора (концепт)
Экран-контур для будущей аналитики. Возможные KPI: число заказов, распределение по статусам, готовые к выдаче устройства, дефицитные позиции склада. Сейчас `panel.php` показывает список заказов и фильтры, а не отдельный dashboard с вычисленными карточками. Не следует считать этот концепт готовым функционалом.
